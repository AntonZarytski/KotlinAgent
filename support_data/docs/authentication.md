# Руководство по аутентификации в KotlinAgent

## Обзор

KotlinAgent использует токен-based аутентификацию через API ключи Anthropic Claude.

## Настройка аутентификации

### 1. Получение API ключа

1. Зарегистрируйтесь на [console.anthropic.com](https://console.anthropic.com)
2. Перейдите в раздел "API Keys"
3. Создайте новый API ключ
4. Скопируйте ключ (он начинается с `sk-ant-`)

### 2. Конфигурация в проекте

Создайте файл `.env` в корне проекта:

```bash
ANTHROPIC_API_KEY=sk-ant-api03-your-key-here
```

### 3. Проверка конфигурации

Запустите health check:

```bash
curl http://localhost:8000/health
```

Ответ должен содержать `"api_key_configured": true`

## Распространенные проблемы

### Ошибка "Invalid credentials"

**Причины:**
1. API ключ не установлен в переменных окружения
2. API ключ неверный или истек
3. Файл `.env` не загружен

**Решение:**
1. Проверьте наличие файла `.env` в корне проекта
2. Убедитесь, что ключ начинается с `sk-ant-`
3. Перезапустите сервер после изменения `.env`
4. Проверьте логи сервера на наличие ошибок загрузки конфигурации

### Письмо для сброса пароля не приходит

**Примечание:** KotlinAgent использует API ключи, а не пароли пользователей. 
Сброс пароля не требуется. Если вы потеряли API ключ:

1. Войдите в консоль Anthropic
2. Отзовите старый ключ
3. Создайте новый ключ
4. Обновите `.env` файл

## Безопасность

### Рекомендации:

1. **Никогда не коммитьте `.env` файл в Git**
   - Добавьте `.env` в `.gitignore`
   
2. **Используйте разные ключи для разных окружений**
   - Development: отдельный ключ
   - Production: отдельный ключ
   
3. **Регулярно ротируйте API ключи**
   - Рекомендуется менять ключи каждые 90 дней

4. **Ограничьте доступ к ключам**
   - Храните ключи в безопасном месте
   - Используйте менеджеры секретов в production

## Двухфакторная аутентификация (2FA)

В текущей версии KotlinAgent не поддерживает 2FA, так как использует API ключи Anthropic.

Для дополнительной безопасности рекомендуется:
1. Включить 2FA в вашем аккаунте Anthropic
2. Использовать IP whitelist в production
3. Настроить rate limiting на уровне сервера

## API Endpoints

### Health Check
```
GET /health
```

Проверяет статус сервера и конфигурацию API ключа.

### Chat API
```
POST /api/chat
Headers:
  Content-Type: application/json
  
Body:
{
  "message": "Ваш вопрос",
  "session_id": "optional-session-id"
}
```

Требует корректно настроенный ANTHROPIC_API_KEY.

## Troubleshooting

### Логи аутентификации

Проверьте логи сервера:
```bash
tail -f logs/application.log | grep "API"
```

Ищите сообщения:
- `✅ API ключ загружен`
- `❌ ANTHROPIC_API_KEY не найден`

### Тестирование подключения

Используйте тестовый скрипт:
```bash
curl -X POST http://localhost:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "test", "session_id": "test"}'
```

Если получаете ошибку аутентификации, проверьте:
1. Сервер запущен
2. `.env` файл существует
3. API ключ валидный
4. Нет проблем с сетью
