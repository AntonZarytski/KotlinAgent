# Руководство по цепочкам MCP инструментов

## Обзор

Агент теперь может **последовательно вызывать несколько MCP инструментов** и использовать результаты предыдущих вызовов для следующих действий.

## Как это работает

### 1. Автоматическое планирование (Claude сам решает)

Claude может самостоятельно планировать последовательность вызовов без специальных инструментов:

**Пример запроса:**
```
Найди файл ClaudeClient.kt и покажи метод sendMessage
```

**Что делает Claude:**
1. Вызывает `git_repository` с действием `search_files` для поиска файла
2. Получает путь к файлу из результата
3. Вызывает `git_repository` с действием `read_file` используя найденный путь
4. Показывает содержимое метода

### 2. С помощью ToolChainMcp (для сложных задач)

Для более сложных сценариев можно использовать `plan_tool_chain`:

**Пример запроса:**
```
Проверь погоду на завтра и создай напоминание если будет дождь
```

**Что делает Claude:**
1. Вызывает `plan_tool_chain` для планирования
2. Получает план: weather → conditional reminder
3. Вызывает `weather` для получения прогноза
4. Анализирует результат
5. Если дождь - вызывает `reminder` для создания напоминания

## Примеры использования

### Пример 1: Поиск и чтение файла

**Запрос:**
```
Найди все файлы с "TokenMetrics" в названии и покажи содержимое главного
```

**Последовательность:**
```
1. git_repository.search_files("TokenMetrics")
   → Результат: ["TokenMetricsService.kt", "TokenMetricsTest.kt"]

2. git_repository.read_file("TokenMetricsService.kt")
   → Результат: содержимое файла

3. Текстовый ответ с содержимым
```

### Пример 2: Погода + напоминание

**Запрос:**
```
Какая погода будет завтра? Если дождь - напомни взять зонт
```

**Последовательность:**
```
1. weather.get_weather_forecast()
   → Результат: {"temperature": 15, "condition": "rain", ...}

2. reminder.create_reminder({
     "text": "Взять зонт - будет дождь",
     "datetime": "2026-01-17T08:00:00"
   })
   → Результат: {"id": "123", "created": true}

3. Текстовый ответ: "Завтра дождь, создал напоминание взять зонт"
```

### Пример 3: Поиск TODO + создание тикета

**Запрос:**
```
Найди все TODO в проекте и создай тикет для самого важного
```

**Последовательность:**
```
1. git_repository.search_in_files("TODO")
   → Результат: список файлов с TODO

2. git_repository.read_file("важный_файл.kt")
   → Результат: содержимое с TODO

3. support.create_ticket({
     "title": "Реализовать важную фичу",
     "description": "TODO из файла важный_файл.kt",
     "priority": "high"
   })
   → Результат: {"ticket_id": "TASK-123"}

4. Текстовый ответ с информацией о созданном тикете
```

### Пример 4: Анализ кода + рекомендации

**Запрос:**
```
Найди файл с ошибкой в обработке токенов и предложи исправление
```

**Последовательность:**
```
1. git_repository.search_in_files("token")
   → Результат: список файлов

2. git_repository.read_file("ClaudeClient.kt")
   → Результат: код с обработкой токенов

3. Анализ кода (внутренний процесс Claude)

4. Текстовый ответ с найденной ошибкой и предложением исправления
```

## Доступные комбинации инструментов

### Git Repository (поиск → чтение)
- `search_files` → `read_file`
- `search_in_files` → `read_file`
- `list_directory` → `read_file`

### Weather → Reminder
- `get_weather_forecast` → `create_reminder` (условно)

### Git Repository → Support
- `search_in_files` → `create_ticket`
- `read_file` → `create_ticket`

### Git Repository → Android Studio
- `read_file` → `analyze_code`
- `search_files` → `open_file`

### Help → Git Repository
- `search_documentation` → `read_file` (для примеров кода)

## Системный промпт

Агент получает следующие инструкции:

```
РАБОТА С ИНСТРУМЕНТАМИ:
- Можешь вызывать несколько инструментов последовательно
- Используй результаты предыдущих инструментов для следующих вызовов
- Например: сначала найди файл (git_repository), потом прочитай его (git_repository)
- Или: получи погоду (weather), потом создай напоминание (reminder) на основе прогноза
- Результаты всех инструментов доступны тебе в контексте
- Планируй последовательность действий для достижения цели
```

## Ограничения

1. **Максимум итераций**: 20 вызовов инструментов на один запрос
2. **Детекция зацикливания**: Если один инструмент вызывается >7 раз подряд - останавливается
3. **Размер результатов**: Большие результаты (>2000 символов) обрезаются для экономии токенов

## Отладка

Для просмотра последовательности вызовов:
1. Включите `show_intermediate_messages: true` в запросе
2. Проверьте логи сервера - там видны все вызовы инструментов
3. Используйте `/api/metrics` для просмотра статистики использования

## Советы по использованию

### ✅ Хорошие запросы (автоматически создают цепочки)

- "Найди файл X и покажи функцию Y"
- "Проверь погоду и напомни если холодно"
- "Найди все ошибки в коде и создай тикеты"
- "Покажи содержимое конфига и объясни настройки"

### ❌ Плохие запросы (не используют цепочки)

- "Покажи погоду" (один инструмент)
- "Создай напоминание" (один инструмент)
- "Что ты умеешь?" (без инструментов)

## Технические детали

### Накопление результатов

Результаты инструментов накапливаются в `accumulatedToolResults` (ThreadLocal):
- Ключ: название инструмента
- Значение: последний результат
- Очищается после финального ответа

### Передача контекста

Claude получает результаты через `tool_result` блоки в истории сообщений:
```json
{
  "role": "user",
  "content": [
    {
      "type": "tool_result",
      "tool_use_id": "123",
      "content": "результат инструмента"
    }
  ]
}
```

### Оптимизация токенов

- Большие результаты обрезаются (McpResultsFilterService)
- История сжимается после 4 сообщений
- Контекст итераций ограничен 4 последними сообщениями
