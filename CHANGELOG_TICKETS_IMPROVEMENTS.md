# Улучшения системы управления тикетами

## Дата: 14.01.2026

### 1. Улучшена логика автоматического создания тикетов ✅

**Проблема:**
Тикеты создавались слишком часто - даже для обычных вопросов типа "Как сделать X?" или запросов документации.

**Решение:**
Обновлен промпт в `SupportService.analyzeProblem()` для более точного определения необходимости создания тикета.

**Новые критерии создания тикета:**

✅ **Тикет СОЗДАЕТСЯ** когда пользователь:
- Явно сообщает что что-то "не работает", "не получается", "выдает ошибку", "сломалось"
- Описывает техническую проблему с конкретным проектом или функциональностью
- Сообщает о баге, сбое, неожиданном поведении системы
- Просит помощь в исправлении неисправности
- Указывает на проблему, требующую отслеживания и решения

Примеры: 
- "У меня не запускается сервер"
- "Выдает ошибку при компиляции"
- "Не работает авторизация"
- "Приложение крашится при запуске"

❌ **Тикет НЕ СОЗДАЕТСЯ** для:
- Общих вопросов типа "Как сделать X?", "Что такое Y?", "Где найти Z?"
- Запросов документации, примеров кода, инструкций
- Консультационных вопросов о том, как что-то реализовать
- Благодарностей, обратной связи, комментариев
- Просьб объяснить концепцию или технологию
- Вопросов о лучших практиках или рекомендациях

Примеры:
- "Как создать REST API?"
- "Объясни что такое Kotlin coroutines"
- "Покажи пример использования"
- "Спасибо за помощь"

**Измененные файлы:**
- `remoteAgentServer/src/main/kotlin/com/claude/agent/service/SupportService.kt`

### 3. Реализовано автоматическое удаление закрытых тикетов ✅

**Проблема:**
Закрытые тикеты оставались в базе данных и списке, загромождая интерфейс.

**Решение:**
Реализовано автоматическое удаление тикетов при изменении статуса на `CLOSED`:

**Серверная часть:**
- `TicketRepository.updateTicket()` теперь автоматически удаляет тикет после установки статуса `CLOSED`
- Метод возвращает `null` когда тикет удален
- Добавлено логирование удаления: `"Auto-deleting closed ticket: {ticketId}"`

**Клиентская часть:**
- `ApiClient.updateTicket()` теперь возвращает `SupportTicket?` (nullable)
- Обрабатывает ответ 404 и пустой ответ как удаление тикета
- UI автоматически закрывает модальное окно и обновляет список при удалении

**Поведение:**
1. Пользователь нажимает "🔒 Закрыть" на тикете
2. Сервер обновляет статус на `CLOSED` и сразу удаляет тикет из БД
3. Сервер возвращает 404 Not Found
4. UI закрывает модальное окно детального просмотра
5. UI обновляет список тикетов (удаленный тикет исчезает)

**Измененные файлы:**
- `remoteAgentServer/src/main/kotlin/com/claude/agent/database/TicketRepository.kt`
- `compose-ui/src/jsMain/kotlin/com/claude/agent/ui/ApiClient.kt`
- `compose-ui/src/jsMain/kotlin/com/claude/agent/ui/App.kt`

### 4. Исправлена проблема с устаревшей сборкой UI ✅

**Проблема:**
При запуске сервера через `./gradlew :remoteAgentServer:run` или другие команды UI не всегда пересобирался, что приводило к отображению старой версии интерфейса.

**Решение:**
Настроена автоматическая пересборка UI при **ЛЮБОМ** запуске сервера:

**Изменения в `remoteAgentServer/build.gradle.kts`:**
- Создана задача `buildUI` которая **ВСЕГДА** выполняется (без кеширования)
- `buildUI` добавлена как зависимость для всех задач сборки:
  - `processResources`
  - `run`
  - `installDist`
  - `jar`
  - `classes` (для IntelliJ IDEA)

**Изменения в `compose-ui/build.gradle.kts`:**
- Удалена очистка Kotlin/JS кеша (вызывала ошибки компиляции)
- Оставлена только очистка webpack кеша и dist
- Все критические задачи помечены как `outputs.upToDateWhen { false }`

**Результат:**
- UI **ВСЕГДА** пересобирается при запуске сервера
- BuildInfo.kt всегда содержит актуальное время сборки
- Не важно как запускается сервер - UI будет свежим

**Измененные файлы:**
- `remoteAgentServer/build.gradle.kts`
- `compose-ui/build.gradle.kts`

### 5. Система уведомлений о действиях с тикетами ✅

**Проблема:**
Пользователь не получал уведомлений в чате о действиях с тикетами (создание, изменение статуса). Ассистент мог автоматически менять статус тикета на RESOLVED на основе своих предположений.

**Решение:**
Реализована полноценная система уведомлений и строгий контроль изменения статусов:

**1. Уведомления в чате:**
- При создании тикета в чат добавляется сообщение:
  - `🎫 Тикет T-001 создан автоматически: [название] (приоритет: 🟡 MEDIUM)`
- При изменении статуса в чат добавляется сообщение:
  - `🎫 Тикет T-001 изменен: OPEN → ✅ RESOLVED`
  - `🎫 Тикет T-001 закрыт и удален: RESOLVED → 🔒 CLOSED`
- Эмодзи для статусов:
  - 🆕 OPEN
  - 🔄 IN_PROGRESS
  - ⏳ WAITING_FOR_USER
  - ✅ RESOLVED
  - 🔒 CLOSED

**2. Контроль изменения статусов:**
- Статус тикета изменяется **ТОЛЬКО**:
  - Когда пользователь нажимает кнопку в UI (✅ Решено, 🔒 Закрыть, 🔄 В работу)
  - Когда пользователь явно подтверждает решение проблемы
- Ассистент **НЕ МОЖЕТ** автоматически менять статус на основе предположений
- Удалена логика автоматического предложения изменить статус на RESOLVED

**3. WebSocket уведомления:**
- При изменении статуса отправляется WebSocket сообщение типа `ticket_status_changed`
- Содержит информацию о старом и новом статусе
- UI получает real-time обновления

**Изменения в коде:**

**`TicketRepository.kt`:**
- Добавлена модель `TicketUpdateResult` с информацией о старом/новом статусе
- Метод `updateTicket()` теперь возвращает `TicketUpdateResult` вместо `SupportTicket?`
- Сохраняется информация о том, был ли тикет удален

**`SupportRoutes.kt`:**
- Добавлены параметры `webSocketService` и `conversationRepository`
- При обновлении тикета:
  - Сохраняется системное сообщение в БД
  - Отправляется WebSocket уведомление
  - Логируется изменение статуса

**`ChatRoutes.kt`:**
- При создании тикета сохраняется системное сообщение в чат
- Добавлены эмодзи для приоритетов (🟢 LOW, 🟡 MEDIUM, 🟠 HIGH, 🔴 CRITICAL)

**`SupportService.kt`:**
- Удалена логика автоматического предложения изменить статус на RESOLVED
- Обновлен промпт: "НЕ предлагай автоматически изменить статус тикета"

**Результат:**
- ✅ Пользователь видит все действия с тикетами в чате
- ✅ Статус тикета изменяется только по явному подтверждению
- ✅ Real-time обновления через WebSocket
- ✅ Полная прозрачность работы с тикетами
